# Прототип CD: Ansible и штатный Git-sync PrairieLearn

Экспериментальный пакет по поручению владельца от 7 ноября 2026 года.
Он проверяет доставку готового курса на изолированной копии установки.
Рабочая VM продолжает обслуживать опубликованные курсы.

## Состав

- `deploy.yml` — стандартные модули Ansible: POST sync, ожидание GET status,
  проверка `Success`, передача и распаковка готового student-сайта.
- `inventory.example.ini`, `vars.example.yml` — примеры входных настроек.
- `workflow.example.yml` — пример ручного вызова того же playbook в Actions.
  Файл находится вне `.github/workflows` и автоматически не запускается.

Существующий exporter, готовый native export, student-сайт и опубликованный
Community 2.5.8 используются повторно. В playbook нет обращения к внутренним
модулям PrairieLearn, SQL-записи оценок или собственного импортёра.

## Граница эксперимента

Копия получает отдельную БД после начисления 82 зачётов и отдельные каталоги.
Доступ к ней ограничен loopback. Workspace-хост и Docker socket отсутствуют.
Токен создаётся обычной формой Settings только в копии. Привязка курса к Git
задаётся штатной административной страницей.

Git-remote в эксперименте — локальный bare-репозиторий с готовым native export.
Это проверяет Git-sync PrairieLearn. Доступ к будущему закрытому репозиторию
GitHub и работа self-hosted runner этим экспериментом не подтверждаются.

Два прогона: исходный экспорт, затем commit с безопасной правкой README.
Веса, UUID и состав заданий сохраняются. После повторной синхронизации
сверяются существующие зачёты и остальные нулевые пункты. Полный прогон
385 сценариев и повторная сборка курса для этого не требуются.

Student-архив распаковывается в новый каталог выпуска. Переключение рабочего
Nginx на этот каталог в эксперимент не входит. Если распаковка не удалась
после успешного native sync, playbook завершится ошибкой; автоматического
отката БД или обещания атомарного обновления двух частей здесь нет.

## Запуск

Команды выполняются из каталога `examples/course-cd/`.
Контроллеру нужны уже установленный Ansible и SSH-доступ в сеть VM.
На удалённой стороне нужен Python. Дополнительные Ansible collections
не используются. Приватные inventory, variables, PAT, БД и журналы хранятся
отдельно от этого пакета.

```sh
ansible-playbook -i /private/inventory.ini deploy.yml -e @/private/vars.yml
```

Переменная окружения `COURSE_CD_TOKEN` передаёт PAT копии установки.
Задачи с токеном используют `no_log`. POST выполняется однократно;
ожидание повторяет только GET. После ошибки POST или native sync следует
посмотреть результат задания, прежде чем отдельно повторять доставку.

Пример Actions предназначен для закрытого репозитория CD и runner внутри
доступной сети. Для такого репозитория пакет копируется в его корень,
а `workflow.example.yml` — в `.github/workflows/`. Inventory и vars указывают пути, подготовленные на runner;
архив сайта и Git-ветка должны быть подготовлены до запуска job.
Подготовка выпуска, загрузка artifacts и подключение runner остаются
следующим этапом. Это прототип доставки, а не включённый production CD.

## Фактический результат

Оба прохода завершены успешно на Community 2.5.8 с Ansible Core 2.21.5:

- Первое штатное задание sync №7 клонировало исходный Git export.
- Задание №8 получило следующий commit с изменением только `README.md`.
- Git HEAD и native `course.commit_hash` обновились до
  `a2f7cc609e0aa3ca8fc55dd2998e04b345da6f65`.
- Все значения 353 вопросов и 31 лабораторной записи сохранились точно:
  82 полных зачёта у 9 студентов, остальные 271 пункт — нулевые.
- Студенческие варианты и ответы не создавались. Механизм `recognized_credit`
  не использовался; число его событий осталось равным нулю.
- Ansible дважды доставил готовый сайт. Проверенные `index.html` и ZIP стартера
  совпадают с исходным artifact побайтно.
- Рабочая установка healthy и не перезапускалась. Контейнер копии остановлен;
  его данные сохранены для повторного опыта.

Краткий результат без персональных данных: [result.json](result.json).
Приватные снимки, токен и журналы хранятся отдельно от этого пакета.
Независимая рецензия конфигурации не обнаружила блокирующих замечаний.

Гипотеза подтверждена для штатной Git-синхронизации подготовленного экспорта
и повторного обновления с неизменными весами и составом заданий. Изменение
весов уже начатых работ в этом опыте не проверялось.
