# Результат внешней проверки

Штатный grader записывает в `results/results.json` безопасную студенческую проекцию. Модуль `runtime/student_feedback.py` обслуживает Java и fish. Приватные журналы, stdout/stderr, stack traces, произвольные сообщения Throwable, исходники эталонов и служебные пути не копируются в студенческий результат.

Java implementation показывает полный достоверно завершённый набор независимых JUnit-листьев. Имя берётся из доверенного `@DisplayName` либо имени parameterized/dynamic случая. При `weighted` доля равна passed/total: контейнер, factory, API precheck и несколько assertions одного листа не добавляют баллов. Соотношение 80/20 задаётся assessment через autoPoints/manualPoints; runner не умножает результат на 0.8.

Публичный `publicCases` содержит уже объявленные name, input/state/action и expected. Контекст объединяется с карточкой единственного связанного JUnit-листа. Для protocol 2 уникальность подтверждается только при полном наборе MethodSource bindings. Неоднозначная или неполная связь даёт `unknown` с причиной; доказанное отсутствие проверки в полном наборе — `not-run`. Отсутствие необязательного TestReporter observation само по себе не меняет фактический passed/failed завершённого листа.

Непривязанный публичный контекст остаётся видимым в основном сообщении без дополнительной балльной карточки. Неисполненные и неизвестные публичные сценарии не получают выдуманные points/max_points. Старый protocol 1 и fish сохраняют собственный путь явно объявленных observations.

Поддержанные обычные JUnit assertions наблюдаются доверенным адаптером в месте вызова. Передаются фактические expected/actual, допуск и поддержанные сведения о первом различии: индекс, строка, столбец и короткие фрагменты. Вызов исходного JUnit сохраняется; ленивое сообщение не вычисляется дополнительно. Закрытый исходник теста не делает его предметные имя и аргументы секретными: автор предназначает эти значения студенту. Неподдержанное или непрозрачное значение обозначается как неполное, без выдуманных данных. Подробности механизма — в [описании assertion feedback](junit-assertion-feedback.md).

TestReporter может явно публиковать предметные expected/actual либо actual для объявленного публичного сценария. Adapter связывает запись с разрешённым test binding. Сообщения assertion и поля `AssertionFailedError` не служат источником публичных значений: студент способен сам создать исключение и изменить его stack trace. Произвольный `toString()` студенческого объекта не вызывается.

Подробности карточки передаются в native `tests[].message`, которое штатный `pl-external-grader-results` выводит в `<pre>`. Краткое `description` содержит итог. Так input/state/action, LF, expected/actual, допуск и diff не зависят от схлопывания пробелов обычного `<li>`. Длинные строки используют штатную прокрутку PL; визуальная приёмка фактического браузера проводится отдельно.

Компиляция и API mismatch при достоверном собственном дефекте дают ноль текущей попытки. Зависимые тесты не выполнялись, поэтому их провалы не создаются. Диагностика компилятора показывает собственный файл, строку и русскую категорию причины без текста исходника и внутренних путей. Успешный API precheck остаётся в приватном отчёте и не создаёт балльный случай.

Различаются runtime, timeout, output limit, wrong answer и сбой проверяющей среды. Последний имеет `grading_error`, `gradable:false` и не содержит score. Неполный XML/план, skipped/aborted листья, container failure, повреждение аутентификации и переполнение сумм объявленных points не дают частичную студенческую оценку. Численные веса отдельных листьев и их суммы должны оставаться конечными.

Вложенная JVM использует точные доверенные типы canonical JavaProcess для runtime, timeout и output limit. Отсутствующий либо подменённый companion — инфраструктурный отказ. Ошибка подготовки доверенного ProcessPort не считается отказом программы. Код завершения сам по себе не доказывает необработанное исключение.

Операторский `--verification` выбирает вызывающий инструмент, а не descriptor или upload. Приватный результат хранится отдельно от студенческих файлов. Host checks, локальная контейнерная проверка, настоящий UI и production — разные уровни свидетельств; успех одного не означает приёмку остальных. Сохранность прежнего best/manual проверяется на native интеграционной границе отдельно.
