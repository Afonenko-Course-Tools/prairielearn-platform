# Platform 2.5.2 — кандидат узкого launch исправления

Builder вызывает прежний installed C entry абсолютным путём с cwd владельца
`source/book`. Новый необязательный `--export-stage` позволяет выбрать literal
output arguments до RME и независимого prior P. Это не разрешение запуска.
Случайный default stage и общий validation/publication tail сохраняются.

Удержанные filesystem identities и parent lock действуют до cleanup;
заменённые/чужие/уже опубликованные данные не удаляются по старому имени.
Основная ошибка сохраняется с notes о cleanup и фактическом результате.
Подробности и эксплуатационные предпосылки — [qualified launch](../qualified-launch.md).

Actual C/native course, full135, P, hosted CI и выпуск не подтверждаются unit
fixtures. Нужны отдельные четыре OCI и три authenticated assets/readback;
2.5.1 не переименовывается и не используется как новое свидетельство.
